# Видалення фону через Photoroom — куди класти ключ

## Головне

**Ключ Photoroom НЕ можна вставляти в `index.html`.** Сайт статичний (GitHub Pages) — його код бачить кожен, тож ключ одразу вкрадуть і витратять ваш оплачений ліміт.

Тому ключ живе у **Cloudflare Worker** (безкоштовно, 100 000 запитів/добу). Сайт звертається до Worker, Worker підставляє ключ і питає Photoroom.

```
Сайт (loomiq.net)  →  Worker (ключ тут)  →  Photoroom API
```

## Налаштування (10 хвилин, робиться один раз)

### 1. Створити Worker

```bash
cd worker
npx wrangler login          # відкриє браузер, увійдіть у Cloudflare
npx wrangler deploy
```

Після деплою Cloudflare покаже URL, напр.:
`https://loomiq-photoroom.ВАШ-АКАУНТ.workers.dev`

### 2. Покласти ключ у секрети

```bash
npx wrangler secret put PHOTOROOM_API_KEY
```

Термінал попросить вставити ключ — вставте його **тільки туди**. Ключ шифрується на боці Cloudflare, у репозиторії його немає.

> Ключ ніде більше не пишемо: ні в коді, ні в чаті, ні в адмінці.

### 3. Вказати адресу Worker в адмінці

Адмінка → **Конструктор сайту** → **Головна й контакти** → блок
**«Видалення фону логотипів (Photoroom)»** → вставити URL Worker → «Зберегти».

Адреса Worker не є секретом — її можна зберігати в адмінці.

## Як це працює на сайті

- **URL заданий** → фон прибирає Photoroom (якісно, складні лого/фото).
- **URL не заданий або сервіс не відповів** → автоматично працює вбудований алгоритм (як раніше). Сайт не ламається ніколи.

## Перевірка

```bash
curl -X POST "https://loomiq-photoroom.ВАШ-АКАУНТ.workers.dev" \
  -H "Origin: https://loomiq.net" \
  -H "Content-Type: image/png" \
  --data-binary "@test.png" -o out.png
```

`out.png` має бути з прозорим фоном.

## Захист від чужих витрат

У `wrangler.toml` у змінній `ALLOWED_ORIGINS` перелічені домени, яким дозволено користуватись проксі. Запити з інших сайтів отримають `403` — сторонні не витратять ваш ліміт.

Якщо міняєте домен — оновіть `ALLOWED_ORIGINS` і зробіть `npx wrangler deploy` знову.

# Замовлення з сайту в Telegram із файлами

Файл `lead-telegram.js` — заміна старого воркера заявок. Він робить те саме,
що й раніше, плюс прикріплює до замовлення файли: логотипи документом
(без стиснення, придатні для друку) і погоджені макети фото.

## Що потрібно

1. Токен бота від [@BotFather](https://t.me/BotFather)
2. Id чату, куди слати (свій або групи)

## Розгортання

```bash
cd worker
npx wrangler login
npx wrangler deploy lead-telegram.js --name loomiq-lead
npx wrangler secret put TELEGRAM_BOT_TOKEN --name loomiq-lead
npx wrangler secret put TELEGRAM_CHAT_ID  --name loomiq-lead
```

Адреса воркера має збігатись із тією, що вказана на сайті в
`LOOMIQ_CONFIG.leadEndpoint` — зараз це `https://loomiq-lead.stvory.workers.dev`.
Якщо розгорнете під іншою назвою, поміняйте адресу в `index.html`.

## Як перевірити

Зробіть тестове замовлення на сайті. У Telegram має прийти **одне**
повідомлення з іменем, телефоном, сумою і розписаними нанесеннями,
а слідом — файли логотипів і макетів із підписами, який це товар,
яка сторона й який розмір нанесення.

Якщо якийсь файл не прикріпиться, воркер напише про це окремим рядком —
посилання на нього все одно є в тексті замовлення.

# Генерація логотипів через Gemini

Файл `gemini-proxy.js` — воркер `loomiq-gemini`. Менеджер в адмінці пише опис,
воркер просить Gemini намалювати зображення й віддає готовий PNG.
Ключ Google живе лише в секретах Cloudflare — у коді сайту його немає.

## Розгортання

```bash
cd worker
npx wrangler deploy gemini-proxy.js --name loomiq-gemini
npx wrangler secret put GEMINI_API_KEY --name loomiq-gemini
```

Або через сайт Cloudflare: Workers & Pages → воркер `loomiq-gemini` →
**Edit code** → вставити вміст `gemini-proxy.js` → **Deploy**; далі
Settings → Variables and secrets → Add → тип **Secret**, ім'я `GEMINI_API_KEY`.

> Ім'я секрету має бути саме `GEMINI_API_KEY` — без пробілів. Воркер вміє
> підхопити ключ і під іншим ім'ям (шукає значення виду `AIza…`), але це
> запасний варіант, а не норма.

## Як користуватись

Адмінка → **Прорахунок** → додати нанесення → «Згенерувати через Gemini».

Два сценарії:

- **З нуля.** Описати логотип словами або натиснути одну зі швидких кнопок
  («Мінімалістична емблема», «Монограма з літер», «Значок у колі»).
- **З фото клієнта.** Скріпка → прикріпити референс. Кнопки міняються на
  обробку фото: «Витягнути логотип із фото», «Векторизувати і стилізувати»,
  «Одноколірний для вишивки». Це для випадків, коли клієнт кидає знімок
  логотипа на спині, під кутом або поганої якості.

Фото зменшується до 1400 px і йде у воркер разом із запитом. Результат
проходить через `loomiq-photoroom`, щоб фон став прозорим.

Тексти швидких кнопок задані в `index.html` (`AI_QUICK`).

## Перевірка

```bash
curl -X POST "https://loomiq-gemini.stvory.workers.dev" \
  -H "Origin: https://loomiq.net" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"minimal line-art mountain logo"}' -o out.png
```

Якщо замість картинки прийшов JSON — у полі `error` буде причина
(`no-image`, `gemini-failed` зі статусом тощо).

# Telegram-вебхук — звідки прийшов той, хто написав

## Навіщо

Клік «Написати в Telegram» видно в аналітиці, а далі слід обривається.
Людина пише боту, менеджер домовляється — і найдорожчі заявки виявляються
без джерела: незрозуміло, яка реклама їх привела.

Сайт дописує до посилання `?start=v<мітка пристрою>`. Telegram передає цей
рядок боту першим повідомленням. Воркер ловить його і кладе в базу, а
адмінка зшиває діалог із візитом за тією ж міткою.

Переписку не зберігаємо — лише хто, коли і скільки разів написав.

## Налаштування (робиться один раз)

### 1. Викотити воркер

```bash
cd worker
npx wrangler deploy telegram-webhook.js --name loomiq-tg --compatibility-date 2024-11-01
```

Cloudflare покаже адресу, напр. `https://loomiq-tg.ВАШ-АКАУНТ.workers.dev`.

### 2. Задати змінні

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN --name loomiq-tg   # той самий бот, що і для заявок
npx wrangler secret put TG_WEBHOOK_SECRET  --name loomiq-tg   # будь-який довгий випадковий рядок, вигадайте самі
```

Ідентифікатор проєкту секретом не є — його задають у Cloudflare →
Worker `loomiq-tg` → Settings → Variables:

```
FIREBASE_PROJECT = loomiq-admin
```

### 3. Сказати Telegram, куди слати

Один раз, у терміналі. Підставте свій токен, адресу воркера і той самий
секрет, що на кроці 2:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://loomiq-tg.ВАШ-АКАУНТ.workers.dev",
       "secret_token":"<ТОЙ САМИЙ СЕКРЕТ>",
       "allowed_updates":["message"]}'
```

Має відповісти `{"ok":true,...}`.

> Токен бота нікуди більше не вставляємо: ні в код сайту, ні в адмінку.

### 4. Опублікувати правила бази

`firestore.rules` містить блок `an_tg` — без нього воркер не запише нічого.
Firebase Console → Firestore Database → Rules → вставити файл → Publish.

## Перевірка

1. Відкрити сайт, натиснути «Написати в Telegram» — має відкритись бот із
   кнопкою «Запустити».
2. Натиснути її, написати будь-що.
3. Адмінка → **06 Аналітика** → **Трафік** → блок **«Діалоги з Telegram»**.
   Має зʼявитись рядок з іменем і каналом, з якого людина прийшла.

Якщо рядок є, а канал — прочерк: людина писала боту раніше, ніж зайшла на
сайт, або відкрила посилання не з сайту. Це нормально.

## Чого цей спосіб не вміє

- **Viber.** Особистий номер (`viber://chat?number=…`) мітку не передає.
  Потрібен Viber Public Account — тоді працює той самий принцип через
  параметр `context`.
- **Дзвінки.** Номер один для всіх, тож зіставити дзвінок із візитом
  неможливо без колтрекінгу (окремий платний сервіс із підміною номера).
- **Instagram Direct.** Мітку передає лише посилання виду `ig.me/m/акаунт?ref=`,
  і лише при переході саме за ним.


## Якщо ботом уже керує ManyChat (або інший конструктор)

Telegram тримає **один вебхук на бота**. Поставити туди адресу воркера —
означає відключити ManyChat: автовідповіді й воронки перестануть працювати.

Перевірити, хто зараз володіє ботом:

```
https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo
```

Якщо в `url` стоїть `wh.manychat.com/...` — бот за ManyChat.

**Рішення: воркер стає передпокоєм.** Він забирає мітку для аналітики й
пересилає запит далі, у ManyChat. Той навіть не помічає різниці.

1. Скопіюйте адресу ManyChat з `getWebhookInfo` — цілком, з усім хвостом
2. Cloudflare → воркер → Settings → Variables → додайте звичайну змінну
   (не секрет): `FORWARD_URL` = ця адреса
3. Тепер переведіть вебхук на воркер:

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://loomiq-tg.ВАШ.workers.dev&secret_token=<СЕКРЕТ>
```

Порядок важливий: спершу `FORWARD_URL`, потім `setWebhook`. Інакше між
двома діями бот кілька секунд відповідатиме без ManyChat.

Перевірка: напишіть боту — ManyChat має відповісти як завжди, а в адмінці
з'явиться рядок у «Діалогах з Telegram».

> **Застереження.** Якщо в ManyChat перепідключити канал Telegram, він
> перезапише вебхук на себе, і аналітика тихо замовкне. Після будь-яких дій
> з каналом у ManyChat перевіряйте `getWebhookInfo` і за потреби повторюйте
> крок 3.
